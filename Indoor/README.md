# Indoor unit — Raspberry Pi 5 doorbell dashboard

Full-screen PySide6 dashboard (home screen in Qt Quick) for a 12.3-inch HDMI touch display. When the outdoor Tuya
doorbell is pressed it receives an MQTT start command, plays the bell sound on
the paired Bluetooth speaker and shows the VIGI camera feed with a STOP button.

```
Outdoor (T5AI)                    broker (Mosquitto on the Pi)          Indoor (this app)
  press ── start {timer,event_id} ───────────────────────────────────▶  ack {event_id}
        ◀─────────────────────────────────────────────────────────────  (outdoor resends every 2 s, max 3x, until acked)
                                                                         bell sound + camera + countdown
        ◀── stop ─────────────────────────────────────────────────────  STOP pressed
  back to main screen
```

## Install

On Raspberry Pi OS (Bookworm):

```bash
sudo apt update
sudo apt install -y python3-venv python3-pip python3-pyside6.qtwidgets python3-pyside6.qtcore \
    python3-pyside6.qtgui python3-pygame python3-opencv mosquitto mosquitto-clients
python3 -m venv --system-site-packages .venv
source .venv/bin/activate
pip install paho-mqtt
```

If the Qt/PySide6 apt packages are not available for your OS release, install the
packages in `requirements.txt` into the virtual environment instead.

Replace `assets/bell.wav` with the bell sound you want.

## MQTT broker (Mosquitto on the Pi)

Mosquitto 2 only accepts connections from the Pi itself by default. The outdoor
unit connects over Wi-Fi, so open a LAN listener:

```bash
sudo tee /etc/mosquitto/conf.d/doorbell.conf <<'EOF'
listener 1883
allow_anonymous true
EOF
sudo systemctl enable --now mosquitto
sudo systemctl restart mosquitto
```

If the Pi runs the UFW firewall (`sudo ufw status` shows `active`), also let the
LAN reach the broker; otherwise the outdoor unit's connection is silently dropped:

```bash
sudo ufw allow from 192.168.2.0/24 to any port 1883 proto tcp comment doorbell-mqtt
```

`allow_anonymous true` is for a prototype on a trusted home LAN. For normal use
add a password file and set the same username/password in `config.json` and in
`DOORBELL_MQTT_USER` / `DOORBELL_MQTT_PASS` in `Outdoor/src/doorbell_net.h`.

Find the Pi's address with `hostname -I` and enter it on the outdoor unit:
hold the bell screen for 5 s → Indoor Unit → Set address. Give the Pi a fixed
address (DHCP reservation on the router) so this does not change.

`mqtt.host` in `config.json` stays `127.0.0.1` when the broker runs on the Pi.

## Settings screen

**⚙ Settings** on the dashboard (top right):

- **Speaker** — search for Bluetooth speakers, pair and connect (the speaker becomes
  the sound output and reconnects automatically at start-up), volume, test sound.
- **News** — any mix of regions (Global, India, Karnataka, Bangalore) and genres for the
  headlines on the main page; the selected regions' news is interleaved. Headlines come from Google News RSS (no API key),
  refresh every 15 min and are cached in `news_cache.json` for offline starts.
  The tile on the main page switches between headlines and the photo slideshow; it is
  labelled with the view it switches to (**Photos** while news shows, **News** while photos show).
- **Bell tone** — choose the sound played for the whole ring; ▶ previews it. 14 original
  tones in three groups — *Chimes*, *Bollywood style* (shehnai, sitar, dhol, santoor with
  tabla and tanpura) and *Funny* — generated by `tools/make_tones.py`. Put your own
  `.wav`, `.mp3` or `.ogg` files (for example film songs you own) in `assets/tones/mine/`:
  they appear under *My tones* and are never committed to git.
- **Outdoor unit** — theme, bell colour, bell style, ring duration, Wi-Fi network and the broker
  address of the outdoor doorbell, applied over MQTT. Needs outdoor firmware with
  remote configuration (built 24 Oct 2026 or later). Text is entered with the
  on-screen keyboard.

Choices made here are saved in `settings.json` (created on first change).

## Bluetooth speaker from the command line

The settings screen does this for you. By hand, the bell plays on the system's default audio output, so make the speaker the default:

```bash
bluetoothctl
  power on
  scan on            # wait for the speaker, note its MAC
  pair  XX:XX:XX:XX:XX:XX
  trust XX:XX:XX:XX:XX:XX
  connect XX:XX:XX:XX:XX:XX
  quit
wpctl status                 # find the speaker under Audio → Sinks
wpctl set-default <sink-id>
```

`trust` makes the speaker reconnect automatically after a reboot. Run the app as
the desktop user (not with `sudo`), otherwise it cannot reach the user's audio session.

## VIGI camera

Set `camera.rtsp_url` in `config.json`:

```json
"camera": { "rtsp_url": "rtsp://USERNAME:PASSWORD@CAMERA_IP:554/stream1" }
```

- `stream1` is the main (full-resolution) stream, `stream2` the sub stream. The Pi 5
  decodes H.264 in software; if the CPU is busy or the picture stutters, use `stream2`.
- USERNAME/PASSWORD are the camera's device account. URL-encode special characters
  in the password (for example `@` → `%40`).
- Check the URL first on any PC with VLC: Media → Open Network Stream.

The stream is opened when a ring starts and closed when it ends, so the first
picture takes a second or two. If the camera is unreachable the ring screen
says so and keeps retrying; the bell and STOP work regardless.

## Run

```bash
source .venv/bin/activate
python app.py
```

The app starts fullscreen. For windowed development: `DOORBELL_FULLSCREEN=0 python app.py`

### Start at boot

```bash
sh ~/Indoor/autostart/install.sh
```

This adds `~/.config/autostart/indoor-dashboard.desktop`, so the dashboard starts
with the desktop after boot (the Pi must log in to the desktop automatically:
`sudo raspi-config` → System Options → Boot / Auto Login → Desktop Autologin).
`autostart/start.sh` restarts the app if it crashes, keeps a single instance, and
logs to `~/Indoor/app.log`. To stop it: `pkill -f "python3 app.py"`.
To remove autostart: `rm ~/.config/autostart/indoor-dashboard.desktop`.

## MQTT commands

See `topics.md`. To test without the outdoor unit:

```bash
mosquitto_sub -h 127.0.0.1 -t 'home/doorbell/#' -v &          # watch everything
mosquitto_pub -h 127.0.0.1 -t home/doorbell/start -m '{"command":"start","timer":20,"event_id":"test-001"}'
mosquitto_pub -h 127.0.0.1 -t home/doorbell/stop -m stop
```

The first publish shows an ack with `"status":"received"`; publishing the same
start again while it rings shows `"status":"duplicate"` and changes nothing.

## Behaviour

- Start received: acknowledged on `home/doorbell/ack`, bell loops, camera feed and
  countdown shown. Further starts while ringing are acknowledged but ignored.
- STOP pressed: sound and camera stop, the dashboard returns, and a stop is
  published so the outdoor unit returns to its main screen.
- Stop received or timer expired: same, without publishing a stop.
- `demo_mode: true` in `config.json` simulates a ring every 18 s for UI testing.

## Current limitations

Photos, news, weather, the scenic carousel and the smart-home controls on the
dashboard are placeholders. The MQTT link is unauthenticated and unencrypted
(see the broker section).
